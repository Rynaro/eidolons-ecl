# Example — APIVR-Δ ↔ VIGIL escalation

A worked example of an escalation: APIVR-Δ hits its 3-failure
threshold on a flaky test, escalates to VIGIL, receives a root-cause
report with a verified patch, applies it, and closes the thread with an
ACKNOWLEDGE.

## Files

- `repair-failed-report.md` — APIVR-Δ output (frontmatter conforms to
  `repair-failed-report.v1.json`)
- `root-cause-report.md` — VIGIL output (frontmatter conforms to
  `root-cause-report.v1.json`)
- `ack.md` — generated by `run.sh`; tiny closeout payload
- `run.sh` — emits the three envelopes and validates the chain

## Run it

```bash
bash run.sh
```

Expected output:

- Three `*.envelope.json` sidecars and three trace events sharing one
  `thread_id`.
- Conformance check passes MUST level for all three envelopes (exit 0).
- The trace summary at the end shows: APIVR `ESCALATE` → VIGIL,
  VIGIL `PROPOSE` → APIVR, APIVR `ACKNOWLEDGE` → VIGIL.

## What this example demonstrates

- **`ESCALATE` performative.** Distinct from `REQUEST` — encodes the
  policy boundary that APIVR-Δ has exhausted its repair budget and is
  routing to a higher-authority agent.
- **`trust_level: high` on the escalation edge.** The contract for
  `apivr → vigil` declares `trust_level: high` because escalations
  carry sandbox authority and may bypass user prompts. This trust level
  flows into every envelope on the edge.
- **Causal chain via `parent_id`.** VIGIL's `parent_id` points at the
  ESCALATE envelope; APIVR's ACKNOWLEDGE points at VIGIL's PROPOSE.
- **Bidirectional thread.** The same `thread_id` carries both
  directions of the consultation; the trace makes the full conversation
  recoverable from disk alone.
- **Methodology gates encoded in frontmatter.** The repair-failed-report
  profile requires `attempts >= 3` (APIVR-Δ P0); the root-cause-report
  profile requires `reproduction_runs >= 2` and `hypotheses_count >= 3`
  (VIGIL P0). The conformance checker validates these as part of
  payload-frontmatter conformance.
