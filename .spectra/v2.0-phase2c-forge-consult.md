## Frame

Does ECL v2.0.0 need a Py envelope verifier in `reference-sdk/py/` to satisfy SDK-tier parity, or is a verifier a feature decoupled from the major version bump and safely deferrable to v2.1?

## Observe (load-bearing facts)

- **Zero current consumers** of a Py verifier: no Eidolon imports the Py SDK at runtime (APIVR-Δ uses hand-rolled jq+shasum on vendored v1.0 schemas); nexus `composition-drift.yml` uses zipapp tools (`migrate`, `a2a-translate`, `eval`) that don't verify envelopes.
- **User's stated frame** is operator-side ("use the new ECL properly"), not Eidolon-side.
- **SDK-tier symmetry is aspirational, not contractual.** The spec mandates a reference verifier (bash) and permits SDKs; it does not require every SDK to verify.
- **v2.0 is a drift-closure release** (DC-1, DC-3), with one open drift candidate (D-03: TS `from`-field divergence from bash). Adding a third verifier implementation creates a new drift vector at the moment we're paying to reduce drift.
- **Reversibility is high:** a Py verifier added in v2.1 is additive — no schema change, no `$id` bump, no major version needed.

## Reason (hypotheses)

**H1 — Defer (SPECTRA's call).** Parity gap is theoretical without a consumer. Maintenance surface grows by zero; v2.0 PR diff stays scoped to drift closure + schema bumps.

**H2 — Ship full Py verifier.** Symmetry-completing; pre-positions Py as a first-class SDK. Costs: ~300–500 LoC + fixtures + parity tests against bash; adds a third drift vector exactly when we're closing two; expands an already-heavy PR.

**H3 — Shell-out wrapper.** Thin Py function subprocessing `conformance/check.sh`. Parity-by-construction. Costs: bash dependency at Py boundary (Windows pain); locks public API signature into v2.0 — future native impl is constrained by the wrapper's perf/error shape. Lock-in for zero current callers.

**H4 — Stub-with-NotImplementedError (FORGE-generated).** Reserve the public-API symbol; raise `NotImplementedError("planned v2.1; use TS SDK or bash conformance")`. Surfaces the gap as deliberate. Net negative: discoverable broken stub is an operator footgun; arguably worse than absent.

## Emit

**Verdict: DEFER (H1).**

Three load-bearing reasons:

1. **No consumer = no parity gap that matters.** Parity becomes load-bearing only when a workflow depends on the missing surface. Neither Eidolons nor nexus do.
2. **Drift posture.** v2.0 is closing DC-1 + DC-3. Introducing a third verifier implementation creates a new candidate drift vector (potential Py-vs-bash) while paying down two others. Net drift posture worsens.
3. **Cheap to add later, expensive to remove.** A v2.1 Py verifier is purely additive (no major bump). Shipping now creates a permanent three-language maintenance surface with no offsetting consumer demand.

**Reversal trigger (single condition):**
> Flip DEFER → SHIP (H2) if any Eidolon's v2.0-adoption PR introduces a runtime Py-side envelope verification call site.

That converts D-03 from aspirational drift to a live consumer gap and inverts the parity-value column.

**Recommended addendum to SPECTRA's plan:** in v2.0 release notes / CHANGELOG, add one line: "Py SDK does not yet ship `envelope_verify`; use TS SDK or `conformance/check.sh` for Py-side workflows. Tracked as D-03; planned additive in v2.1." Converts an absence into a documented decision and pre-empts adopter confusion. APIVR-Δ to land this line as part of DECISION-S3 implementation.
